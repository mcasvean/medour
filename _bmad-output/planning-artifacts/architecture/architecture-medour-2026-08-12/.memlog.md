- (direction) Mode: Coaching path. Input: SPEC.md (8 CAPs). Deliverable: spine only.
- (decision) AD-1: Monorepo, two top-level folders: client/ (Vue 3 + Vite + TypeScript) and server/ (Spring Boot Java). Binds: all code lives in one repo; FE and BE are independently buildable units in distinct folders. Prevents: mixing server code into client tree or vice versa.
- (decision) AD-2: Real-time transport is SSE (Server-Sent Events). Server pushes slot state and appointment status changes; clients never push via the real-time channel. Binds: Spring SseEmitter on BE; EventSource API on FE. Prevents: WebSocket infrastructure for v1.
- (decision) AD-3: JWT stored in localStorage on the client. Binds: Vue app reads token from localStorage; sends as Authorization Bearer header. Prevents: httpOnly cookie approach for v1. Assumption: XSS surface is low for v1; upgrade to httpOnly cookie flagged as security hardening for v2.
- (decision) AD-4: BE package structure layered by technical role: controller/, service/, repository/, model/, config/, security/. Binds: all Spring components in their respective layer package. Prevents: feature-folder organisation for v1.
- (decision) AD-5: Slot locking via dedicated slot_reservations table (doctor_id, date, start_time, reserved_by_patient_id, reserved_at, expires_at) with unique constraint on (doctor_id, date, start_time). INSERT fires SSE push to all active clients immediately; DELETE (cancel or expiry) fires SSE release. Atomic INSERT prevents concurrent double-lock. Prevents: optimistic locking on appointment row, Redis-based TTL.
- (decision) AD-6: Soft-delete on users table via deleted_at TIMESTAMP NULL (null=active, non-null=deleted). No hard DELETE on users. Deleted user data (name, speciality) remains in DB and is readable on appointment cards. FE renders a 'Removed' badge on any appointment card referencing a soft-deleted user. Login with soft-deleted user credentials returns the same generic invalid-credentials error as a non-existent account. Prevents: hard delete with snapshot columns; prevents leaking deletion status through distinct error messages.
- (decision) AD-7: Whereby room created via Whereby API at appointment save time. Room URL stored in appointments.whereby_room_url. Prevents: lazy creation at Join click.
- (decision) AD-8: Doctor average_rating stored as DECIMAL(3,1) on users table, recalculated and rounded to 1 decimal on every rating insert or edit. Prevents: AVG computed at query time; prevents 2+ decimal precision.
- (decision) AD-9: Auto-cancel via Spring @Scheduled fixed-rate every 60s; queries Open appointments where scheduled_start + 10min < NOW(); sets Auto-Canceled + fires SSE push. Single-instance v1 only.
- (decision) AD-10: FE state via Pinia; one store per domain: authStore, appointmentStore, userStore, doctorStore. No Vuex.
- (decision) AD-11: Axios HTTP client; request interceptor injects Authorization: Bearer from localStorage; response interceptor catches 401 and triggers logout.
- (decision) AD-12 [ADOPTED]: REST API; Spring @RestController; all endpoints under /api/v1/; JSON request/response.
- (decision) AD-13 [ADOPTED]: Vue Router for FE routing; role-based navigation guards on protected routes; redirect to /login if no valid token.
- (decision) AD-14 [ADOPTED]: Spring Data JPA + Hibernate ORM; repositories extend JpaRepository.
- (decision) AD-15 [ADOPTED]: Spring Security for role-based route protection; roles: PATIENT, DOCTOR, ADMIN stored in JWT claims.
